# orbital-shell-typescript — open gaps

Every open gap this repo owns lives here. This file is the source of truth; the monorepo's `docs/Almadar_Gaps.md` only rolls it up.

- **One entry per gap:** `- **<code>** — <what is wrong and where>. <owning package> [mechanical|architectural] — <evidence, prevention rung>`.
- **Codes:** new gaps use this repo's prefix `G-ORBITAL-SHELL-TYPESCRIPT-`. Take the "Next code" below, then bump it in the same edit. Codes are never reused or renamed.
- **Close by deleting.** Remove the entry in the same commit as the fix.

- **G-ORBITAL-SHELL-TYPESCRIPT-025** — The kernel-hosted client still ships more of the program than any client code path reads. Done 2026-10-18: the template's client build keeps source maps and splits the kernel, ui, react, three and firebase packages into their own chunks (`manualChunks` in `vite.config.ts`; `std-crm` builds at the default Node heap, 4,288 MB limit, peak heapUsed 2.9-3.8 GB, RSS 5.0 GB, 15 s; the unsplit build died at 4.7 GB) and the client runs a projection (`program.client.json`, `client_program` in `kernel_host.rs`) without `_metadata`, `ledger`, and each trait's `effectRow` and `sourceEntityDefinition`: no Rust kernel code and no client TS path reads them (`OrbPreview` reads `sourceEntityDefinition` only under `autoMock`, which a transport-backed preview skips). Sizes: `std-crm` 4,580,950 to 4,002,248 B (gzip 605 to 548 KB), `std-studio` 9,141,072 to 8,158,287 B. Open: the earlier 2.9 MB estimate counted keys the client does read, so it is not reachable by dropping keys: `eventId` (client `StateMachineCore` and emit-stamp routing), event and emit `description`/`synonyms`/`tier` (agent ports, so the assistant dock), and config knob descriptions (unproven). Done 2026-10-18: the projection ships as the static asset `packages/client/public/program.client.json` the client fetches at boot (`loadProgram` in `client-program.ts`), so it is no longer in the JS bundle (`std-crm` JS 17.65 to 13.06 MB; the asset is 4.0 MB, 542 KB gzip, served by vite in dev and from `dist` by the hono static server and any static host). Closing the rest needs a recorded read set of the client kernel per path (a traced run of `std-crm` and `std-studio`), then a declared per-path drop list. orbital-shell-typescript kernel host (`kernel_host.rs`) [architectural] — evidence: `orb compile std-crm.lolo --shell typescript`, sizes of `packages/client/src/program.client.json` against `packages/shared/src/program.json`. Prevention rung 3 (`orb verify --compiled` builds the client at the default heap). found 2026-10-18

- **G-ORBITAL-SHELL-TYPESCRIPT-029** — The web client (`templates/almadar-shell/packages/client`) never mounts `PersonaSwitcher` (`features/auth/components/PersonaSwitcher.tsx`, exported from `features/auth`): with the Auth emulator on, `/api/personas` answers the roster but the page offers no way to pick a persona, so a person can only sign in through the email/Google form; the verifiers use `window.__almadarAuth`. Seen 2026-10-19 under `orb serve` on `std-project-manager` (roster of 3, no switcher on `/` or `/login`). Wanted: the switcher rendered (login page and the signed-in chrome) while the served config names an Auth emulator, with a test that a roster shows it and an empty roster does not. `orbital-shell-typescript` template [mechanical] — prevention rung: `runtime-verify` (an emitted dev affordance that never renders).
- **G-ORBITAL-SHELL-TYPESCRIPT-030** — The web client mounts the program before a stored sign-in restores: `KernelApp` renders with `viewer` undefined, every INIT dispatches anonymously and the native server answers 401, then the `key` change remounts it signed in and the INITs succeed. Seen 2026-10-19 under `orb serve` (`std-project-manager`, persona signed in, a reload: 5 x 401 then 200 on `HomeOrbital`, the same on `ProjectOrbital`). Wanted: `KernelApp` waits for the auth state to settle (signed in or known signed out) before mounting `OrbPreview`, with a test that a restored session sends no anonymous dispatch and a control that a signed-out page still mounts. `orbital-shell-typescript` template [mechanical] — prevention rung: `runtime-verify` (requests refused before the viewer is known).

- **G-ORBITAL-SHELL-TYPESCRIPT-008** — The kernel host (`host kernel`, K7) is Express only: its server mounts `OrbitalServerRuntime.router()`, an Express router, so `framework hono` with `host kernel` is refused. A Hono kernel host needs a Hono router on the runtime (`@almadar/runtime`), not a second adapter here. Prevention rung: none of the language rungs (shell option matrix); the gate is the refusal test in `shell_program.rs`. [architectural]
- **G-ORBITAL-SHELL-TYPESCRIPT-009** — A kernel-hosted app's `packages/{server,client}/package.json` gain `@almadar/kernel`, `@almadar/db` and `@almadar/std` by text insertion after the template copy (`add_dependencies`), while the template's `pnpm-lock.yaml` files keep the old dependency set, so `pnpm install --frozen-lockfile` fails until the lockfiles are regenerated; `@almadar/kernel` is also not yet on npm. - **G-ORBITAL-SHELL-TYPESCRIPT-003** — Nothing typechecks a full-mode compile of a real organism: std-kflow's `orb compile --mode full` emitted 559 client tsc errors (a `let` named `fields` shadowing the shell mirror, views without `now` for `time/relative`, unparenthesized union array casts, raw `array/sum`/`array/range` operands, payload-sourced mapped children, required `string | number` props cast with `| undefined`, computed `entity` lists, awaiting-skeleton literals, nested object-prop members, deep client entity reads, nullable arithmetic operands, `SExpr` handler payloads, literal persist rows); each class is fixed with a unit test (2026-10-12), but the next class will again only surface in a deploy. Add a gate that compiles a fixed set of organisms (std-kflow, std-notes, one game and one learning lab) in full mode and runs `tsc --noEmit` on client and server. Prevention rung: that compiled-typecheck gate (`orb verify --compiled` or the crate's CI). `[architectural]`
- **G-ORBITAL-SHELL-TYPESCRIPT-004** — Email-link sign-in loses the page the viewer was sent from: the template `Login.tsx` completes the link with `history.replaceState(…, '/login')` and then navigates to `/` because the `returnTo` navigation state did not survive the email round trip. A viewer gated off `/home` lands on the public `/` after signing in by link (Google popup and password keep `returnTo`). Carry `returnTo` through the link's `continueUrl`. Prevention rung: a template unit test for each sign-in method returning to `returnTo`. [mechanical]

- **G-ORBITAL-SHELL-TYPESCRIPT-006** — The compiled path ignores a theme's loading artwork.
  - **Runtime path (done, 2026-10-12):** `@almadar/ui` `themeTokensToCssVars` emits `illustration.loadingAsset`, and the dark variant's override, as `--illustration-loading: url("…")` plus `--loader-mark-display: inline-block` / `--loader-icon-display: none`. `Spinner` paints that mark in place of its icon.
  - **Missing here:** `codegen/theme` `emit_skin_axes` / `emit_skin_axes_dark` emit nothing for `illustration`. A compiled app (std-kflow, std-nata, std-rawi) therefore keeps the generic spinner, although `@almadar/core` `themes/{kflow,nata,rawi}.json` declare the orbital marks.
  - **Fix:** emit the same three variables from the same fields, with a twin of `packages/almadar-ui/test/themeTokens.illustration-axis.test.ts` and its control.
  - **Prevention rung:** none of the language rungs (a runtime/compiled parity gap). The tooling gate is that twin test. `[mechanical]`
