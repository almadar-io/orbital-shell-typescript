Next code: `G-ORBITAL-SHELL-TYPESCRIPT-015`


- **G-ORBITAL-SHELL-TYPESCRIPT-013** — After a mutation, a generated server re-sends a `ref`'s rows as the ref's own filtered page only when the ref's filter reads nothing but `@user`/`@config` and every ref of that entity agrees. A filter reading `@payload`/`@entity`, a ref by id, or a non-literal limit still re-sends the viewer's whole `@read`-scoped set, because the refreshing handler cannot evaluate another handler's request bindings. Also, the generated `pushUpdate`/`pushDelete` refusal path (policy false → no write, `@update denied`) is so far checked only by type, never run. Fix: carry the ref's resolved query (bindings applied at load time) with the ref so a refresh replays it, and add a generated-app test over `CountingPersistence` asserting one `queryPage` per refresh and a refused guarded write. `orbital-shell-typescript` [architectural] — evidence: S9 follow-up 2026-10-14; prevention rung: none of the language rungs (generated host behavior), gated by the generated-app test.

- **G-ORBITAL-SHELL-TYPESCRIPT-008** — The kernel host (`host kernel`, K7) is Express only: its server mounts `OrbitalServerRuntime.router()`, an Express router, so `framework hono` with `host kernel` is refused. A Hono kernel host needs a Hono router on the runtime (`@almadar/runtime`), not a second adapter here. Prevention rung: none of the language rungs (shell option matrix); the gate is the refusal test in `shell_program.rs`. [architectural]
- **G-ORBITAL-SHELL-TYPESCRIPT-009** — A kernel-hosted app's `packages/{server,client}/package.json` gain `@almadar/kernel`, `@almadar/db` and `@almadar/std` by text insertion after the template copy (`add_dependencies`), while the template's `pnpm-lock.yaml` files keep the old dependency set, so `pnpm install --frozen-lockfile` fails until the lockfiles are regenerated; `@almadar/kernel` is also not yet on npm. Prevention rung: the compiled-typecheck gate of G-ORBITAL-SHELL-TYPESCRIPT-003 run on the kernel host. [mechanical]

- **G-ORBITAL-SHELL-TYPESCRIPT-007** — Compiled `std-notes` and `std-ecommerce` clients still fail `tsc` (4 errors each, local orb + workspace packages, 2026-10-12): (1) a list's literal `itemActions` carry `navigatesTo`, which the synthesized action element type does not declare (TS2352) — the action-element schema and the `.lolo` disagree on `navigatesTo`; (2) a mapped literal button reads `icon` through `getNestedValue(s, "icon") ?? "arrow-right"`, the wide `FieldValue` (TS2322 against `IconInput`); (3) the history router's `beginNavigate` title coalesce passes the wide payload read (TS2345). Also `std-crm` (compilable since G-ORBITAL-CORE-001, 9 errors): the same `navigatesTo` and `icon` shapes, plus inline-extracted render traits (`InlineDividerRender*`, `InlineStackRender*`) emitting the raw string `"@config.enter"` into the `enter` motion prop instead of the resolved config value (TS2322). None comes from the G-ORB-242 fixes. Repro: `orb compile <organism> --mode client`, then `tsc --noEmit -p packages/client` against the workspace packages. Prevention rung: G-ORBITAL-SHELL-TYPESCRIPT-003's compiled-typecheck gate. [mechanical]
- **G-ORBITAL-SHELL-TYPESCRIPT-005** — Mapped render-ui children carry no React `key`: `try_mapped_children_jsx` (`codegen/pattern/registry.rs`) emits `{(xs).map((x) => (<Node …/>))}`, so every list (kflow-site-chrome's header links, for one) logs "Each child in a list should have a unique key" and React reconciles rows by index — an inserted or reordered row reuses its neighbour's state. Key by the element's `id` when the row declares one, else by index explicitly. Prevention rung: a pattern codegen unit test asserting `key=` on mapped children. [mechanical]

- **G-ORBITAL-SHELL-TYPESCRIPT-003** — Nothing typechecks a full-mode compile of a real organism: std-kflow's `orb compile --mode full` emitted 559 client tsc errors (a `let` named `fields` shadowing the shell mirror, views without `now` for `time/relative`, unparenthesized union array casts, raw `array/sum`/`array/range` operands, payload-sourced mapped children, required `string | number` props cast with `| undefined`, computed `entity` lists, awaiting-skeleton literals, nested object-prop members, deep client entity reads, nullable arithmetic operands, `SExpr` handler payloads, literal persist rows); each class is fixed with a unit test (2026-10-12), but the next class will again only surface in a deploy. Add a gate that compiles a fixed set of organisms (std-kflow, std-notes, one game and one learning lab) in full mode and runs `tsc --noEmit` on client and server. Prevention rung: that compiled-typecheck gate (`orb verify --compiled` or the crate's CI). `[architectural]`
- **G-ORBITAL-SHELL-TYPESCRIPT-004** — Email-link sign-in loses the page the viewer was sent from: the template `Login.tsx` completes the link with `history.replaceState(…, '/login')` and then navigates to `/` because the `returnTo` navigation state did not survive the email round trip. A viewer gated off `/home` lands on the public `/` after signing in by link (Google popup and password keep `returnTo`). Carry `returnTo` through the link's `continueUrl`. Prevention rung: a template unit test for each sign-in method returning to `returnTo`. [mechanical]

- **G-ORBITAL-SHELL-TYPESCRIPT-002** — The generated server is stateless, so a server-run tick cannot know the trait's current state: `src/backend/server/ticks.rs` fixes `state` to the initial state and cannot honor `appliesTo`; the shared-frame writer driver (`src/codegen/effect/tick.rs`, one driver for several writer traits) has no per-writer state either. Per-trait client ticks honor `appliesTo` since 2026-10-12. Blocked on G-CROSS-160 (D-10, the compiled cascade / one-kernel decision). Prevention rung: `orb verify` tick fixture in a non-initial state on the compiled path. `[architectural]`
- **G-ORBITAL-SHELL-TYPESCRIPT-006** — The compiled path ignores a theme's loading artwork.
  - **Runtime path (done, 2026-10-12):** `@almadar/ui` `themeTokensToCssVars` emits `illustration.loadingAsset`, and the dark variant's override, as `--illustration-loading: url("…")` plus `--loader-mark-display: inline-block` / `--loader-icon-display: none`. `Spinner` paints that mark in place of its icon.
  - **Missing here:** `codegen/theme` `emit_skin_axes` / `emit_skin_axes_dark` emit nothing for `illustration`. A compiled app (std-kflow, std-nata, std-rawi) therefore keeps the generic spinner, although `@almadar/core` `themes/{kflow,nata,rawi}.json` declare the orbital marks.
  - **Fix:** emit the same three variables from the same fields, with a twin of `packages/almadar-ui/test/themeTokens.illustration-axis.test.ts` and its control.
  - **Prevention rung:** none of the language rungs (a runtime/compiled parity gap). The tooling gate is that twin test. `[mechanical]`
