# @almadar/core

## 4.2.0

### Changes

- **Removed `LOLO_TYPE_METADATA` and `LoloTypeMetadata` exports.** The lolo-specific
  type metadata snapshot that was generated by `scripts/build-lolo-type-metadata.ts`
  is no longer shipped. The script and its output (`src/generated/lolo-type-metadata.ts`)
  are deleted. `@almadar/core` is now a pure types package with zero coupling to the
  `.lolo` documentation format.

### Migration

The only consumer of `LOLO_TYPE_METADATA` was `tools/almadar-lolo-types-sync` (the
generator that produces `docs/signatures.lolo`). The extraction logic has been
relocated INTO that tool. After this release, `@almadar-tools/lolo-types-sync` walks
the bundled `dist/schema-*.d.ts` file directly via the TypeScript Compiler API to
produce the same output. No other consumer existed.

If you imported `LOLO_TYPE_METADATA` from `@almadar/core` directly: there is no
replacement export. Walk the `.d.ts` files in the installed `@almadar/core/dist/`
directory yourself, or pin to `@almadar/core@4.1.0`.

### Why

Per the LOLO_Gaps.md consolidation, lolo-specific extraction logic should not live
inside `@almadar/core`. The package should know about types, not about the
documentation format that surfaces those types. This release closes that abstraction
leak. See `docs/LOLO_Gaps.md` and `docs/Almadar_Orb_Behaviors.md` in the kflow.ai.builder
parent repo for the full migration story.
